# Developing LumiPDF

LumiPDF is a [Tauri 2](https://tauri.app) app: a Svelte 5 + TypeScript frontend that renders PDFs
with [pdf.js](https://mozilla.github.io/pdf.js/), and a Rust backend for files, the library,
export, formula sheets and updates.

## Building from source

Requirements: [Node.js](https://nodejs.org) 22+, [Rust](https://rustup.rs) (stable), and the
[Tauri prerequisites](https://tauri.app/start/prerequisites/) for your system.

```sh
npm install
npm run tauri dev      # run the app in development mode
npm run tauri build    # build an installer
```

## Checks

```sh
npm run check                          # type check (Svelte + TypeScript)
npm test                               # frontend unit tests
cargo test --manifest-path src-tauri/Cargo.toml
npm run bench                          # open and render every test PDF in Chromium
node tests/preview/shoot.mjs           # screenshots of the app with sample data
```

The bench writes PNGs and `tests/bench/out/report.html`; the viewer must stay pixel-identical to
plain pdf.js. PDFs placed in `tests/private/` are included in the bench but never committed.

The pictures in the README come from the same mocked app: `python3 scripts/readme-images.py`
rebuilds `docs/images/` (needs Pillow).

## Releasing

> **Before a stable release — remove everything beta-only.** It all lives behind the
> **Settings → Beta** section (`updates.isBeta`), and each piece is marked `BETA BUILDS ONLY`
> in the code (`grep -rn "BETA BUILDS ONLY" src src-tauri`):
>
> - the **Beta** section and its entry in `SECTIONS` (`SettingsScreen.svelte`);
> - "Welcome, from the start": `whatsNew.replayFirstLaunch`;
> - the performance panel: `src/lib/perf/`, `<PerfPanel />` and `perf.restore()` in `App.svelte`,
>   `perf.attach` in `ReaderScreen.svelte`, the `perf_log` command (`src-tauri/src/perf.rs`);
>   keep `ViewerController.stats()` (harmless);
> - photo training: `src/lib/dark/photoTraining.svelte.ts`, `src/lib/dark/ui/PhotoMenu.svelte`,
>   `src/lib/dark/imageSpots.ts` (and `recordSpot` in `engine.ts`), the right-click on `.pages`
>   in `ReaderScreen.svelte`, `setSpotTracking`/`restorePhotoOverrides` in `App.svelte`, the
>   `save_photo_example` command (`perf.rs`). **Keep the photo model** (`photoFeatures.ts`,
>   `photoModelWeights.ts`): it is what the app uses.
>
> The photo model's dataset and training tools live in the private lab repository; only the
> weights (`photoModelWeights.ts`) are copied here.

1. Update `version` in `package.json` and `src-tauri/Cargo.toml`, and add its entry to
   `src/lib/whatsnew/releases.json` (shown in the app after updating, and used as the release
   notes).
2. Push a commit with `[release]` in its message (or a tag `vX.Y.Z`; betas: `X.Y.Z-beta.N`). The
   **Release** workflow tags it, builds the installer signed for the updater and saves a **draft**
   release (installer only; test builds, including the portable exe, come from the CI workflow's
   artifacts).
3. Check the draft and publish it. The **Update channels** workflow then points the in-app updater
   at it (betas reach only users with "Beta versions" on).

The workflow needs the updater key as repository secrets `TAURI_SIGNING_PRIVATE_KEY` and
`TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. Losing the key means installed copies can no longer update.

## Project layout

| Path | Contents |
| --- | --- |
| `src/` | Frontend (Svelte 5 + TypeScript) |
| `src/lib/` | Frontend modules: viewer, dark engine, annotations, sheets, stats, i18n… |
| `src-tauri/` | Backend (Rust, Tauri 2): files, library, export, sheets, updater |
| `tests/unit/` | Frontend unit tests (Vitest) |
| `tests/bench/` | Rendering bench (Playwright) |
| `tests/preview/` | App screenshots with a mocked backend |
| `tests/fixtures/` | Test PDFs, regenerated by `scripts/make-fixtures.py` |
| `docs/images/` | README pictures, built by `scripts/readme-images.py` |
| `.github/workflows/` | CI, releases and update channels |
